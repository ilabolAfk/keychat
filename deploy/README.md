# Развёртывание KeyChat relay на Raspberry Pi

KeyChat использует центральный WebSocket-узел (`relay.py`), через который два
клиента общаются P2P-образно (сообщения, файлы, звонки, голос). Узел **не хранит
содержимое** — только перенаправляет поток, поэтому он очень лёгкий и с запасом
работает даже на Raspberry Pi 3B с 1 ГБ ОЗУ.

## Схема

```
 KeyChat A  ──ws──►  relay.py (RPi)  ◄──ws──  KeyChat B
                     порт 8765
```

## 1. Установка relay на RPi

На RPi (Raspberry Pi OS, подключение по SSH):

```bash
cd ~
# скопируйте папку deploy/ и relay.py на RPi (например по scp):
#   scp -r deploy relay.py pi@<IP>:/home/pi/
# затем на RPi:
cd ~/deploy
sudo apt-get update
bash install_relay.sh
```

Скрипт:
- копирует `relay.py` в `~/keychat-relay/`,
- ставит `websockets`,
- регистрирует systemd-сервис `keychat-relay` (автозапуск + рестарт при падении),
- запускает и показывает статус.

Проверка:
```bash
systemctl status keychat-relay
journalctl -u keychat-relay -f    # логи
```

## 2. Доступ наружу (если клиенты вне LAN)

Relay сам по себе слушает `0.0.0.0:8765`. Чтобы клиенты из интернета достали
порт, пробросьте **TCP 8765** на роутере до IP вашего RPi. Если IP динамический —
подойдёт динамический DNS (например, `duckdns.org`) или положить RPi за VPN.

## 3. Настройка клиентов KeyChat

В каждом клиенте укажите адрес узла переменной окружения перед запуском
(или исправьте `RELAY_URL` в `keychat/network.py`):

Windows (PowerShell):
```powershell
$env:KEYCHAT_RELAY_URL = "ws://192.168.1.50:8765"   # локальный IP RPi
python main.py
```

Linux/macOS:
```bash
export KEYCHAT_RELAY_URL="ws://192.168.1.50:8765"
python main.py
```

Для доступа из интернета вместо локального IP используйте домен:
`ws://mydomain.duckdns.org:8765`.

## 4. FAQ

**Хватает ли 1 ГБ ОЗУ?** Да. Relay хранит только список подключений и пересылает
данные (не записывает на диск постоянно), так что на 1 ГБ занято ~30–60 МБ.

**Что если в сети несколько пользователей?** Relay ничем не ограничивает;
маршрутизация по `user_id` — произвольное число клиентов.

**Реально ли чистый P2P без relay?** Для звонков/сообщений сквозь интернет без
сервера не обойтись (нужен хотя бы сигнальный узел при NAT). Этот relay и есть
минимальный такой узел; сами данные не проходят через его хранилище.
